Choose capabilities

Two profiles. One shared runtime.

A profile is a list of enabled Harness parts and their settings. It controls what runs. Package declarations control what gets installed. We must keep both lists consistent.

Headless

Run a request from the command line. Keep conversation storage, model calls, domain tools, goals, event services, and flows. Add the headless runner.

Do not install the browser UI, browser shell, or web startup package.

Web

Keep the shared runtime. Add browser transport, the current conversation controls, structured forms, presets, goals, and the spec2gds UI.

The small web runtime starts the server and serves the built browser files.

What files belong in a package?

JavaScript · .js
Built code that Node.js or the browser can execute.
Type declarations · .d.ts
Descriptions that help another TypeScript application compile against the package.
Configuration · .yml / .json
Profiles, tool schemas, prompt catalogues, and browser module metadata.
Browser files
Built scripts, styles, fonts, and other files needed by the selected web UI.
Native files
Prebuilt binaries required by the supported operating system and processor.
Metadata and notices
Package name, version, exported entry points, licences, and notices.

Harness source code and its compiler are not required in a downstream production installation.
