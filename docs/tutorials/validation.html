EVIDENCE, NOT ASSUMPTIONS

Validation and learner review

A guide is complete only when its actions and saved-state check have been exercised.

Review gates

The core guides and optional tracks are available for review. A new designer must still complete guides 1–3 and confirm that the format is clear, then complete the full core path and the independent challenge. Until that review is recorded, reading-time estimates and learner independence are unverified. Do not label an automated browser run as a human review.

Run the checks

uv run python scripts/build_tutorials.py --check
uv run python -m pytest tests/test_tutorials.py -q
scripts/test-all.sh fast --output temp/TEMP_tutorials/evidence/fast
scripts/test-all.sh integration --scope spec,circuit,assistant,verification,activities --output temp/TEMP_tutorials/evidence/integration

The fast profile includes exactly three live model checks. Missing credentials or tools make it incomplete. Keep the report’s executed commands, exit results, and coverage limits. Run broad regression if implementation changes cross-application contracts, persistence, shared runtime, or the Activity SDK. This tutorial change does not change those contracts.

Guide acceptance record

For each guide, record its title, code revision, start path, browser, service URLs, prerequisites, elapsed practice time, actions completed, final source revision, expected versus actual result, and evidence paths. Capture at least two focused UI states. Store the run under an ignored repository TEMP_ directory.

  • Reopen the Spec after a successful save.
  • Compare Spec and Circuit after Save to Spec.
  • Check invalid drafts, unavailable tools, stale lint, and missing model credentials.
  • For Assistant exercises, use live model access and inspect saved results; do not require identical prose.
  • For RTL, retain the actual published project and its lint log.
  • For Verification Planner, retain snapshot and checkpoint identities and synthetic evidence provenance.
  • Record SystemC generation, compilation, and simulation separately.

Screenshot maintenance

The page images are focused captures of the actual applications. They illustrate controls and source data; they are not proof of a learner’s run or live model success. Keep capture originals and reports below TEMP_. Publish only selected documentation images in the tutorial assets directory, with no credentials or private design data.

Human review form

  • Can the designer find each control without undocumented help?
  • Does each guide fit its 5–8 minute estimate, excluding installation and tool queue time?
  • Can the designer restart from its prepared checkpoint?
  • Can the designer explain what was saved and what remains unverified?
  • Can the designer complete guide 9 without a supplied click sequence?

Record findings in the evidence directory. Correct instructions and repeat the affected guide before marking the course ready.
