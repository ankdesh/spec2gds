BEFORE YOUR FIRST GUIDE

Environment and checkpoints

Use a ready environment, or prepare a local one without changing the shared service configuration.

Use a ready environment

Ask its maintainer for the Spec Editor, Circuit Designer, and AI Assistant URLs, plus a writable absolute server-local tutorial directory. Default ports are 6010, 6012, and 6013. Verification Planner runs separately on 6016. Use the actual host and ports printed by your environment; 0.0.0.0 is not a browser address.

Keep browser downloads, scratch files, Activity outputs, and validation evidence under the repository’s ignored temp/TEMP_tutorials/ directory. Browser-local paths and server-local paths can refer to different machines.

Prepare a fresh set of starts

On the service host, run this from the repository root after Python setup:

uv run python scripts/prepare_tutorials.py --output temp/TEMP_tutorials/my-run

The command uses the production Spec HTTP API in a private in-process service. It does not need a model or alter a running editor. It creates a separate start for each core lesson, the complete source, a snapshot, a TLM example, and prepared Verification Planner records. It prints absolute paths in starts.json.

Use File → Open Spec to open the start named in a guide. These are real editable files. To reset after editing one, prepare a new directory such as temp/TEMP_tutorials/retry-02. The command refuses an existing output directory. Do not overwrite a start or someone else’s work.

Continue with your own Spec where the previous result matches the next lesson. Guide 5 supplies an additional containing interface; its start includes that setup. Each start is complete for its named lesson. The preparation does not claim lint or simulation success.

Install and start locally

This section is for the environment maintainer. The combined launcher targets Linux or WSL. Install Python 3.12+, uv, Node.js 24.2+, and lsof. RTL checks also need Verilator 5.x and GNU Make. Package setup requires GitHub Packages read access through NODE_AUTH_TOKEN; keep credentials out of files and tutorial screenshots.

scripts/setup-all.sh
uv run python scripts/prepare_tutorials.py --output temp/TEMP_tutorials/my-run

Point this process at the run-local registry so Activity outputs and preferences stay below TEMP_. Keep the tracked registry unchanged:

export SPEC_EDITOR_STATE_ROOT="$PWD/temp/TEMP_tutorials/my-run/spec-state"
export ASSISTANT_STATE="$PWD/temp/TEMP_tutorials/my-run/assistant-state"
export SPEC2GDS_SCRATCH_ROOT="$PWD/temp/TEMP_tutorials/my-run/scratch"
export SPEC_DOCUMENT_ROOT="$PWD/temp/TEMP_tutorials/my-run/documents"
scripts/serve-all.sh start --service-config "$PWD/temp/TEMP_tutorials/my-run/services.json"

Use the printed browser URLs. If model credentials are not already configured, set OPENAI_API_KEY in the launching environment before starting. The first three manual guides work without it. Never paste a credential into a guide, prompt, screenshot, or log.

To use restricted Spec content review in an isolated environment, add --require-designer-approval when starting. Do not restart a shared environment for a tutorial. Stop only the stack that you started:

scripts/serve-all.sh stop

Start Verification Planner separately

uv run verification-planner --service-config temp/TEMP_tutorials/my-run/services.json --storage-dir temp/TEMP_tutorials/my-run/verification/planner-data

Open its printed URL. Select the prepared plans by name in the plan selector. The first guide also shows snapshot upload in New Plan. Later Spec edits do not change the imported snapshot.

The verification/ directory contains a private prepared service data directory, a starts.json file with each plan name and ID, and a clearly marked synthetic result file. To add starts to an already running Verification Planner, give its URL to the preparation command with --planner-url http://127.0.0.1:6016. This adds new tutorial plans and does not modify existing ones. No simulator is run during preparation. Use these prepared plans directly: portable .vplan import currently does not restore all review prerequisites.

Optional SystemC prerequisites

Cycle-accurate generation needs CIRCT, circt-verilog, the native spec2gds-systemc-emit tool, and SystemC. The AT skeleton uses a separate TLM topology; building it needs CMake and SystemC. Follow the current SystemC reference before starting those guides. Keep build output under TEMP_. A missing optional toolchain leaves that guide incomplete.

Read the HTML guides

Open docs/tutorials/index.html directly, or serve the repository locally:

uv run python -m http.server 6080 --bind 127.0.0.1

Then open the local tutorial index. The pages use local CSS and JavaScript, with no package build or external fonts. Reading and navigation also work without JavaScript.
