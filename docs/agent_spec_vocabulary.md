# Agent-Spec V1 Vocabulary

Use these terms consistently in code, APIs, UI text, and documentation.

| Term | Current meaning |
| --- | --- |
| `.spec` package | Deterministic custom ZIP containing canonical source and durable activity metadata. |
| Source | Manifest, narrative AST, IP-XACT documents, assets, and accepted annotations. |
| Activity | Executions, events, reports, artifact metadata, and proposal review state excluded from the source hash. |
| `SpecPackage` | Mutable construction/persistence facade used at explicit package boundaries. |
| `SpecRevision` | Immutable semantic projection of one validated source revision. |
| Source revision hash | SHA-256 identity of canonical source entries, excluding activity. |
| Document ID | Stable package identity shared by the manifest, narrative, and local entity references. |
| Entity ID | Stable XML-ID-compatible identity of one source entity. |
| `EntityRef` | Typed reference consisting of document ID, entity ID, and entity kind. |
| VLNV | IP-XACT `vendor:library:name:version` identity used for protocol-native references. |
| Component | Reusable IP-XACT hardware definition with ports and bus interfaces. |
| Leaf component | Component without an assigned internal design. |
| Composite component | Component mapped to one internal design by the manifest. |
| Design | IP-XACT collection of component instances and connections. |
| Internal design | Design owned by a composite component. |
| Entry design | Explicit top-level design selected in the manifest. Multiple entries are supported. |
| Port | Physical or transactional component endpoint represented below IP-XACT `model/ports`. |
| Bus interface | Formal protocol interface represented below IP-XACT `busInterfaces`. |
| Interconnection | Design connection between bus interfaces. |
| Ad-hoc connection | Design connection between ports or external boundaries. |
| Narrative document | Typed project-owned AST stored at `document/document.json`. |
| Narrative block | Stable section, paragraph, list, table, image, entity link, or live view node. |
| Entity link | Narrative reference to stable source identity. |
| Live view | Read-only rendering derived from current SpecIR data. |
| Asset | Content-addressed source file referenced from narrative. |
| Annotation | Registered optional source input carried into snapshots. |
| Transaction | Atomic ordered source operations tied to an expected source revision hash. |
| Diagnostic | Human-readable validation or artifact-integrity problem; not a silent fallback. |
| Action definition | Trusted versioned contract for an entity-targeted local tool. |
| Action snapshot | Immutable dependency bundle captured for one execution. |
| Action execution | Durable result of invoking an action, including events, report, results, and diagnostics. |
| Artifact | Immutable generated content with verified sidecar bytes and source provenance. |
| Artifact sidecar | Content-addressed filesystem storage outside the `.spec` ZIP. |
| Artifact lineage | Parent relationship between produced and selected input artifacts. |
| Change proposal | Review-gated source operations generated by an action. |
| Preview | Validation of proposal operations against a private source copy. |
| Accept | Reviewed proposal application through the normal transaction validator. |
| Reject | Review decision that leaves source unchanged. |
| Editor snapshot | Complete JSON projection used by the browser to render one revision. |
| Derived topology | Read-only graph computed from design instances and connections, never separate source. |

## Retired Terms

The following belong only to pre-pivot history and must not describe the active
system: ODT container, office document body, heading-derived block, section
version group, editor relation attachment, run callback, A2UI report surface,
and modality plugin manager.
